# VibeForge

**Десктопное приложение, которое превращает одну задачу на естественном языке в работу команды
AI-агентов над реальным репозиторием** — с изоляцией через git, автотестами, ревью диффа до коммита и
осмысленной историей коммитов.

Агенты — это не «чат, который печатает код», а headless-процессы уже установленных у пользователя CLI
(Claude Code, Codex, Grok, Kimi, Gemini) под его собственными подписками. VibeForge — харнес над ними:
планирование, параллельность, изоляция, гейты качества, наблюдаемость и восстановление после сбоев.
Ключевое продуктовое решение: **мы не перепродаём токены** — пользователь платит за оркестрацию
поверх подписок, за которые уже платит.

Роль: единственный разработчик — продукт, архитектура, бэкенд-sidecar, десктоп-UI, iOS-компаньон,
лендинг, релизы. Период: июль 2026, версия 0.1.2, сборки под macOS и Windows.

---

## Как это устроено

```
Tauri-окно (React 19 + Tailwind 4 + Monaco + xterm.js)
        │  WebSocket-протокол с типами из общего пакета
        ▼
Node.js sidecar
        ├── планировщик задач и режимы оркестрации
        ├── абстракция движков: headless CLI-процессы и API-провайдеры
        ├── git-слой: worktrees, ветки, коммиты, merge под мьютексом, resolver
        ├── локальный CI: install / lint / test как гейт перед коммитом
        ├── SQLite (Drizzle) — граф памяти сессии
        └── relay-туннель для удалённого управления с телефона
```

Схема БД — это граф памяти сессии: сессии, задачи, агенты, логи, изменения файлов, ошибки агентов,
использованные расширения. Он же источник для канбана, ленты активности и учёта токенов.

## Четыре режима оркестрации

| | Solo | Swarm | Fusion | Orchestrator |
|---|---|---|---|---|
| Агентов | 1 | 1–6 | 1–6 дебатёров + синтезатор | 1–6 эпиков + resolver |
| Планировщик | нет | нет, делят сами | да | да, режет цель на эпики |
| Где работают | в проекте | одна папка на всех | только читают | каждый в своём git worktree |
| Гейты | verify перед коммитом | verify | verify | автотесты + локальный CI, до 5 итераций |
| Для чего | правки и вопросы | средние задачи из нескольких кусков | спорные решения | крупные фичи под контролем |

**Swarm — это команда, а не N одиночек.** Три фазы: координация (все читают репозиторий и объявляют в
общий чат, кто какие файлы берёт; правки запрещены), реализация, добор сообщений. Агенты пишут друг
другу адресно и всем, конфликт претензий на файл разрешается детерминированным правилом, любой агент
может зафиксировать решение, обязательное для остальных. Плюс файловый watcher: перед своим ходом
каждый воркер узнаёт о чужих правках.

**Fusion — многомодельный дебат.** Три раунда: предложение → критика → конвергенция, причём каждый
дебатёр может работать на движке другого вендора (одна модель против другой на одной задаче).
Дебатёры не трогают файлы — это спор о дизайне; затем отдельный агент-синтезатор получает стенограмму
и реализует победившее решение кодом.

**Orchestrator — изоляция и конвейер.** Планировщик режет цель ровно на столько эпиков, сколько дано
воркеров (со вторым проходом, который дожимает слишком ленивый план). Каждый эпик получает свою ветку
и **git worktree вне каталога проекта** — агенты физически не видят друг друга. Далее на каждый эпик:
итерация агента → локальный CI → коммит только при зелёном CI → ревью диффа человеком → merge строго
по одному под мьютексом. Провал CI возвращается агенту как фидбек (до 5 итераций, потом задача
помечается заблокированной). Конфликт слияния поднимает отдельного resolver-агента.

## Инженерные задачи, которые пришлось решать

### Одна модель событий из разнородных протоколов

Пять CLI-движков и два вида API-провайдеров (Anthropic и OpenAI-совместимые) — у каждого свой
формат потока. Всё нормализуется в единый поток событий, из которого одновременно живут лента
активности, терминалы (xterm.js), канбан, дифф-ревью и учёт токенов по моделям. Добавление нового
движка — это реализация одного адаптера, а не правки по всему приложению.

### Сессия как диалог, а не как задание

Пока сессия работает, сообщение пользователя уходит агентам прямо в текущий разговор (steering); когда
сессия завершена — то же поле ввода создаёт follow-up задачу, и агент возобновляет **ту же** беседу с
полным контекстом. Текст агентов стримится в ленту по мере генерации.

### Устойчивость к лимитам и сбоям

Упор в лимит подписки — не ошибка, а состояние: приложение парсит время сброса из ответа, показывает
бейдж с временем возобновления, ждёт (с потолком и кнопкой отмены) и автоматически продолжает ту же
беседу агента. Отдельно — watchdog фоновых сессий и восстановление после рестарта бэкенда.

### Безопасность как явный слой, а не набор проверок

- Любой путь, пришедший от модели, проходит `realpath` + проверку префикса рабочей директории —
  блокируются `..`, абсолютные пути и symlink-побеги.
- Выполнение команд — только с рабочим каталогом внутри проекта, с таймаутом и блок-листом опасных
  операций (повышение прав, рекурсивное удаление, пуш в удалённый репозиторий, «скачай и выполни»).
- Внешние расширения (Skills/MCP) устанавливаются только после явного подтверждения пользователя, у
  бандла считается sha256, реестр установленного хранится локально.
- Ограничения честно описаны в документации: блок-лист — эвристика, а не песочница. Мне важнее, чтобы
  пользователь знал реальную модель угроз, чем чтобы маркетинг звучал красивее.

### Автокоммиты с человеческим смыслом

Каждый режим завершается коммитом, заголовок которого строится из итогового резюме агента — то есть
описывает суть изменений, а не список файлов. Незакоммиченные правки пользователя перед стартом
уходят в отдельный checkpoint-коммит, чтобы агентская работа была отдельной единицей отката. После
коммита дифф открывается в ревью с кнопками «всё хорошо» / «откатить» (через безопасный `git revert`).

### Продукт вокруг продукта

В том же монорепозитории: нативный iOS-компаньон с виджетом на Swift (~8 500 строк) и relay-туннель,
чтобы следить за сессиями и отвечать агентам с телефона; лицензирование и платёжный сервис; сборка и
публикация релизов под macOS и Windows; лендинг; промо-ролики на Remotion.

### Дизайн-контракт, проверяемый тестом

Единый документ фиксирует палитру (одна нейтральная шкала + ровно один акцент), шкалу типографики,
радиусы и длительности анимаций — и он источник истины сразу для трёх поверхностей: приложения,
лендинга и видео. Отдельно перечислены запрещённые приёмы (градиенты, glassmorphism, sparkle-иконки,
эмодзи в кнопках). Соблюдение проверяется автотестом, а не силой воли.
